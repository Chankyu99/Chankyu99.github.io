# 1일차 : RAG 파이프라인 코드 리팩토링

내가 주로 담당했던 RAG 파이프라인 코드를 리뷰하며, 리팩토링을 겸사겸사 진행했다.

우선 브랜치를 따로 생성하고, 새로운 코드 리팩토링을 진행했다. Codex와 함께 짠 코드를 한 줄씩 한 줄씩 적어가며 작동 원리와 그렇게 코드를 짠 이유를 말할 수 있도록 숙지하려 노력했다.

그래서 bot_logic.py 코드를 먼저 진행했다.

프로젝트의 파이프라인 실행 흐름은 다음과 같다.

1) 사용자 질문 입력 → 슬롯 추출 및 DB 항목 매핑
2) 필수 슬롯 누락 여부 체크 → 누락 시 사용자에게 재질문
3) ChromaDB에서 문서 검색
4) 검색된 문서 + 슬롯 정보를 기반으로 최종 답변 생성
5) Streamlit에 스트리밍 출력

순서대로 코드를 이해한 내용을 정리해본다.

## 1. 국가별 카탈로그 생성

> 슬롯 추출 전, "LLM이 어떤 DB 항목 중에서 고를 수 있는지" JSONL로 저장된 문서를 읽어 국가별 물품 카탈로그를 생성한다.

```python
COUNTRIES = {"KR", "US"}

def load_country_item_catalog():
    items_by_country: dict[str, set[str]] = {country: set() for country in COUNTRIES}

    with open(DATA_FILE, "r", encoding="utf-8") as f:
        for line_num, line in enumerate(f, start=1):
            stripped_line = line.strip()

            if not stripped_line:
                continue

            record = json.loads(stripped_line)
            country = record.get("country")
            item = record.get("item")

            if country not in COUNTRIES:
                continue

            if not isinstance(item, str) or not item.strip():
                continue

            items_by_country[country].add(item.strip())

    return {
        country: sorted(items)
        for country, items in items_by_country.items()
    }
```

- 규정 문서에 있는 공식 물품 카테고리명과 사용자 입력의 물품명을 연결시키기 위한 사전 작업
- 처음 모듈 실행 시, 한 번만 실행해 메모리에 저장해두고 재사용하는 구조

## 6. FALLBACK 메시지

- 다시 생각해보면, 검색 결과가 없을 시 LLM의 일반 지식 추론으로 답하게 할 수도 있었으나, 프로젝트 목적은 항공 규정 RAG 챗봇이라는 점
- 따라서 검색에 실패하면 답을 지어내지 않고, 실패 이유에 따라 메시지를 반환

## 7. 파이프라인 전체 흐름 연결

- 흐름에 따른 함수를 최종 연결해 작동하는 파이프라인 함수를 만들어 실행
- 사용자 질문 입력 -> 슬롯 추출 -> 부족한 정보 있을 시 재질문 -> 충분 시 문서 검색 -> 검색 결과를 바탕으로 답변 생성 -> 없다면 fallback
- 역할별로 함수를 나누어 각 함수가 무엇을 하는 기능인지 쉽게 볼 수 있게 짰다.

```
build_slot_prompt        → LLM에게 보낼 프롬프트 생성
parse_slot_response      → LLM 응답 JSON 파싱
extract_slots_and_map    → 슬롯 추출과 DB 매핑 실행
check_missing_slots      → 필수 정보 누락 확인
retrieve_docs            → ChromaDB 문서 검색
build_retrieved_context  → 검색 문서를 답변용 context로 변환
generate_answer          → 최종 답변 생성
run_pipeline             → 전체 흐름 연결
```

여기까지가 RAG 핵심 파이프라인이 작동하는 방식을 정리한 것이다. 내일은 DB 생성에 필요한 코드를 정리해보자.
