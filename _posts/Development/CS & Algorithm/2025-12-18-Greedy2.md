## 문제

### 문제 설명

점심시간에 도둑이 들어, 일부 학생이 체육복을 도난당했습니다. 다행히 여벌 체육복이 있는 학생이 이들에게 체육복을 빌려주려 합니다. 학생들의 번호는 체격 순으로 매겨져 있어, 바로 앞번호의 학생이나 바로 뒷번호의 학생에게만 체육복을 빌려줄 수 있습니다. 예를 들어, 4번 학생은 3번 학생이나 5번 학생에게만 체육복을 빌려줄 수 있습니다. 체육복이 없으면 수업을 들을 수 없기 때문에 체육복을 적절히 빌려 최대한 많은 학생이 체육수업을 들어야 합니다.

전체 학생의 수 n, 체육복을 도난당한 학생들의 번호가 담긴 배열 lost, 여벌의 체육복을 가져온 학생들의 번호가 담긴 배열 reserve가 매개변수로 주어질 때, 체육수업을 들을 수 있는 학생의 최댓값을 return 하도록 solution 함수를 작성해주세요.

### 제한사항

- 전체 학생의 수는 2명 이상 30명 이하입니다.
- 체육복을 도난당한 학생의 수는 1명 이상 n명 이하이고 중복되는 번호는 없습니다.
- 여벌의 체육복을 가져온 학생의 수는 1명 이상 n명 이하이고 중복되는 번호는 없습니다.
- 여벌 체육복이 있는 학생만 다른 학생에게 체육복을 빌려줄 수 있습니다.
- 여벌 체육복을 가져온 학생이 체육복을 도난당했을 수 있습니다. 이때 이 학생은 체육복을 하나만 도난당했다고 가정하며, 남은 체육복이 하나이기에 다른 학생에게는 체육복을 빌려줄 수 없습니다.

## 입출력 예 설명

### 예제 #1  

1번 학생이 2번 학생에게 체육복을 빌려주고, 3번 학생이나 5번 학생이 4번 학생에게 체육복을 빌려주면 학생 5명이 체육수업을 들을 수 있습니다.

### 예제 #2  

3번 학생이 2번 학생이나 4번 학생에게 체육복을 빌려주면 학생 4명이 체육수업을 들을 수 있습니다.

# 풀이

> 풀이시간 : 1시간 / 내가 직접 풀었는가? : X

```python
def solution(n, lost, reserve):
    
    # 체육복을 가진 사람 수는 순서가 중요하니 정렬 / 잃어버린 사람과 여벌이 있는 사람의 중복 제거
    reserve = sorted(list(set(reserve)-set(lost))) 
    lost = set(lost) - set(reserve)
    
    for i in reserve:
        if i-1 in lost:      # 앞 사람이 잃어버린걸 먼저 확인
            lost.discard(i-1) # 그 사람에게 우선 빌려주기
        elif i+1 in lost:    # 그 다음 뒷 사람이 잃어버린걸 확인
            lost.discard(i+1) 
    
    return n - len(lost)     # 전체 인원 수 - 잃어버린 사람 수 = 체육복이 있는 사람 수
```

# 공부한점

### 그리디 알고리즘의 핵심, 선택의 정당성 검토

만약 2번이 여벌옷을 가지고 뒷 사람(3,4,5)에게 빌려준다면, 1번은 옷을 빌릴 기회가 없다. 3,4,5번은 아직 여별옷을 받을 기회가 있는데도 불구하고! 

그래서 `for`문에서 여벌옷을 가진 사람 기준으로 앞사람에게 우선적으로 빌려주어야 하기 때문에 `if` 조건문의 첫번째 조건이 앞 사람이 잃어버린걸 확인하는 것이 되었다.

### 정확성과 효율성 고려하기

우선, `reserve`배열의 경우,  순서가 중요한 그리디 알고리즘에서 정렬이 매우 중요하다. 최선의 선택이 순서에 의해 결정된다면 정렬이 반드시 필요하다.

`set`을 활용해 리스트의 중복을 제거하였다. 제한사항의 마지막 사항 때문인데, 이를 고려하지 않으면 `lost`와 `reserve`배열이 중복을 가지는 케이스가 반례가 되어버린다. 근데 실제로는 프로그래머스에서 중복을 제거하지 않아도 통과 처리가 되었다.

_중복을 제거하지 않으면 테스트3이 반례가 된다._

### 시간복잡도 
코드 초기에 `reserve`를 정의하는 식에서 집합 생성에 $O(N)$, 차집합에 $O(N)$, 그리고 정렬에 $O(N \log N)$이 걸린다.

처음 코드를 작성할때는 리스트와 `remove` 메서드로 활용했었다. 중복을 고려하지 않았어서 리스트를 쓴 것도 이유지만,  사실 `set`의 `discard`를 활용하면 시간복잡도를 줄일 수 있는 것을 알게 되었다. 

또한 `remove`의 경우 리스트에 요소가 없다면 에러를 발생하지만, `discard`의 경우 에러를 발생시키지 않아 안전성도 한몫한다.

리스트의 경우 $O(n)$, `set`의 경우 $O(1)$로 확연한 차이는 아니지만, 효율적인 것을 추구하는게 좋긴하다.
